Spoonful Code Review Process. Pull requests should be small, ideally under 400 changed lines, with a description of what changed, why, and how it was tested. Automated checks including unit tests, linting and the security scan must pass before review is requested. Changes to production services require two approvals, and at least one must come from a service owner. Documentation-only changes need one approval. Authors may never approve their own pull request. Changes touching authentication, payments or personal data also need sign-off from a Security Champion. Reviewers respond within one business day and label comments as blocking, suggestion or nit. They check correctness, tests, security, performance and readability. After approval the author squash-merges, and the change deploys to staging first, then production after smoke tests pass. On a bad release, the on-call engineer rolls back first and investigates afterwards.
